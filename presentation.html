01  ·  Introduction

Your AI agents, with a shared memory.

Kluris turns a git repository into a brain — a structured knowledge graph that every AI agent on your team reads as a subject matter expert. Human-curated. Git-backed. Portable across Claude Code, Cursor, Windsurf, Codex, Gemini CLI and friends.

Vocabulary · learn this once, everything clicks

BRAIN Brain A git repo of curated knowledge — one per team, tenant, or subject.
LOBE Lobe A folder grouping related neurons (e.g. infrastructure/, knowledge/, projects/).
NEURON Neuron A single markdown file with YAML frontmatter — one durable fact, decision, or runbook.
SYNAPSE Synapse A cross-link between neurons — agents follow them to load related context.

The two-surface mental model · everything in this tour uses it

Terminal You, at the shell

The kluris CLI. You run these yourself — install, create a brain, push/pull changes, regenerate the MRI, refresh skills.

kluris wake-up --brain acme-sme
Inside your AI agent The agent, with the kluris skill loaded

Slash commands the agent runs when you type them in chat. Routes through /kluris (one brain) or /kluris-<name> (two or more).

/kluris-acme-sme learn about checkout
Throughout this tour, a Terminal badge means you, typing in your shell. A Inside your AI agent badge means your AI agent, after you type a slash command in its chat. Same brain. Two surfaces. One source of truth.
02  ·  Install

Install once, in under a minute.

Kluris ships as a Python CLI on PyPI. We install it with pipx so it gets its own isolated environment and a global kluris command — no virtualenvs to activate, no conflicts with your project Pythons.

macOS · zsh/bash Terminal 
$ brew install pipx
$ pipx ensurepath
$ pipx install kluris
Linux · bash Terminal 
$ python3 -m pip install --user pipx
$ pipx ensurepath
$ pipx install kluris
Windows · PowerShell Terminal 
> pip install pipx
> pipx ensurepath
> pipx install kluris
verify the install Terminal 
$ kluris doctor
→ kluris v2.8.2 · Python 3.12.4 · git 2.46
✓ ~/.kluris/config.yml       ready
✓ brains directory            ~/Projects
✓ agent skills installed      claude-code, cursor
✓ all checks passed           you're ready to wake up a brain
Muscle memory: run kluris doctor after every upgrade. It refreshes the agent skill files on disk so your AI picks up the latest slash commands automatically.
Upgrading later: pipx upgrade kluris  ·  then kluris doctor.

What kluris doctor does, in plain English

  • check  confirms your config + brain directory are valid.
  • refresh  re-writes agent skill files to match this CLI version.
  • heal  suggests fixes for anything it can't resolve itself.
03  ·  Create or clone a brain

Start fresh, or join an existing brain.

Every brain is just a git repository. Create one from scratch with an interactive prompt, or clone a teammate's brain exactly like you'd clone any other repo — then run one command to connect it to your agents.

A · Create a new brain

? Brain type:
  › single-project   (one repo, one product)
  › project-group    ← recommended for teams
  › organization     (multiple tenants/groups)
? Parent directory:          ~/Projects

✓ git init                   · first commit
✓ scaffolded lobes           infrastructure/ knowledge/ projects/
✓ wrote brain.md + glossary.md + kluris.yml
✓ installed per-brain skill  /kluris-acme-sme
Next:  cd acme-sme && kluris wake-up

Scaffolded structure

~/Projects/acme-sme 
acme-sme/
├── kluris.yml           # brain config — name, type, lobes
├── brain.md             # the front-door map agents read first
├── glossary.md          # team-specific vocabulary
├── README.md            # humans first — auto-generated on create
├── infrastructure/     # how the system runs
├── knowledge/          # domain facts, policies, decisions
└── projects/           # one sub-folder per repo/product

B · Clone a teammate's brain

kluris clone Terminal 
$ kluris clone git@github.com:acme/acme-sme.git
✓ git clone                  acme-sme/ (main)
✓ read kluris.yml            project-group · v2
✓ registered with CLI        kluris list → now shows 1 brain
✓ installed per-brain skill  /kluris-acme-sme

Next:  kluris wake-up --brain acme-sme
       refreshes the snapshot so the agent loads cleanly.
New laptop? Install kluris, then one kluris clone per brain. That's the whole onboarding — no login, no SaaS, just git.

Pick a brain type that fits

single-project One product, one repo. No projects/ folder.
project-group A team with many related repos — most common choice.
organization Multi-tenant, multi-team. Top-level groups/ folder.
Real examples: btb-sme (single-project: BurnTheBurnout only) and ngvoicu-sme (project-group: kluris, specmint, consensflow). Both live alongside the projects they describe.
Host it anywhere git lives. A kluris brain is a plain git repo — push it to GitHub, GitLab, a self-hosted Gitea, or keep it local. Nothing in kluris is cloud-locked.

4 · 1

Connect your agents once.

Kluris generates an agent skill — a small pack of instructions — for each AI tool you use. You tell kluris which tools; it writes the skill to the right place on disk. After that, every new project automatically has access.

install skills for Claude Code + Cursor Terminal 
$ kluris install-skills
? Which agents? claude-code cursor

✓ ~/.claude/skills/kluris-acme-sme/     (Claude Code)
✓ ~/.cursor/skills/kluris-acme-sme/     (Cursor)
Now open any repo and type /kluris-acme-sme in chat.

Supported agents out-of-the-box

Claude Code Cursor Windsurf GitHub Copilot Codex Gemini CLI Kilo Code Junie
Naming scheme: with one brain on disk the skill is just /kluris. Two or more and it becomes /kluris-<brain-name> — so /kluris-acme-sme, /kluris-btb-sme, /kluris-ngvoicu-sme are each a direct line to a specific brain.

4 · 2

The session wake-up.

Every AI session starts with a clean context window — that's why agents forget. Kluris fixes this with a bootstrap: the first time you invoke the skill in a session, the agent automatically runs kluris wake-up and ingests a fresh snapshot of the whole brain.

in Claude Code / Cursor chat Inside your AI agent 
> /kluris-acme-sme learn about our auth flow

↳ agent runs kluris wake-up --brain acme-sme --json
✓ loaded brain.md             7 lobes · 142 neurons
✓ loaded glossary.md          38 terms
✓ ready
agent: I found four neurons on auth across
       infrastructure/auth/ and projects/api/...

What the agent knows after wake-up

  • map Every lobe, every neuron title, every synapse.
  • glossary Team-specific vocabulary (e.g. "protocol" in btb-sme means the employee evaluation flow).
  • index The brain.md front-door — a curated README for agents.
  • on-demand Neuron bodies are fetched only when needed — context stays lean.
Manual refresh: after a big git pull, run kluris wake-up --brain acme-sme in your terminal and the next agent invocation reads the updated snapshot immediately.

4 · 3

Learn mode — ask the brain anything.

This is the most common interaction. You ask; the agent reads the right neurons; you get an answer grounded in your team's curated knowledge — not in a generic training set and not in last session's vibe.

learn: specmint v1 in ngvoicu-sme Inside your AI agent 
> /kluris-ngvoicu-sme learn about specmint v1 release

agent reads:
  › projects/specmint/release-v1.md
  › projects/specmint/forge-vs-implement.md
  › knowledge/decisions/claude-plugin-marketplace.md  (synapse)

agent: Specmint v1.0.1 ships two plugins — specmint-core and
       specmint-tdd — both pure-markdown, installable via
       claude plugin add ngvoicu/specmint-core.
       Key decision: the TDD fork alternates TEST-IMPL task pairs
       and requires test execution at every phase transition.

Useful learn patterns

ask it anything Agent 
> /kluris-acme-sme learn about how we scale the api
> /kluris-acme-sme what is a protocol?
> /kluris-acme-sme search "rate limit"
> /kluris-acme-sme search "auth" --lobe infrastructure
"What" vs "learn": what looks up a glossary term or a specific neuron by title. learn gathers several related neurons and gives you a synthesis. Use whichever fits.

4 · 4

Remember mode — grow the brain with your agent.

This is how the brain stays alive. You tell your agent something durable — a decision, an incident root-cause, a runbook step — and it proposes a neuron: a draft markdown file with frontmatter and synapses. You read it, edit anything you want, and approve. Then the agent writes it to disk.

remember: a technical decision Inside your AI agent 
> /kluris-acme-sme remember that we rolled back
  from kafka to rabbitmq for the billing queue
  after ordering issues on 2026-03-11.

agent drafts neuron:

  path: infrastructure/messaging/billing-queue-rollback.md

  ---
  id: billing-queue-rollback
  title: Billing queue · rolled back to RabbitMQ
  status: active
  date: 2026-03-11
  synapses:
    - infrastructure/messaging/overview
    - projects/billing/incidents/2026-03-11
  ---

  ## Context
  Kafka ordering guarantees didn't hold under our partition
  key distribution. RabbitMQ restores per-queue ordering.

  ## Decision  — keep until further notice
  ...

> approve                     ← one word, that's it
✓ wrote infrastructure/messaging/billing-queue-rollback.md
✓ updated brain.md map
✓ ready to commit + push

Why the human-in-the-loop step matters

  • grounded The agent can only write what you approved. No extrapolation.
  • reviewable You see the exact file, exact path, exact synapses before it lands.
  • editable Say "change the title to X" or "put it under knowledge/" — the agent redrafts.
  • git-tracked Everything is a diff. Rollbacks, blame, and review happen in your PR tool.
Three remember shapes you'll use often:
· remember that <decision> — captures a choice + rationale.
· remember that we had an incident where... — drafts a post-mortem neuron.
· remember the runbook for restarting X — drafts a step-by-step.

4 · 5

The brain is never locked. Guide, edit, or steer at will.

After the brain has "learned" something, you can still change its mind. Every neuron is just a markdown file — edit it in your editor, commit, push. Tell the agent what to revisit. Deprecate outdated entries. Add brand new lobes whenever a new concern shows up.

edit  Open & edit directly

agent Agent 
> /kluris-acme-sme update
   infrastructure/auth/overview.md
   — add a JWT rotation section

Or open it in your editor yourself — it's a normal file in a normal repo.

new lobe  Add a new folder

terminal Terminal 
$ kluris lobe compliance
✓ created compliance/
✓ linked into brain.md

Lobes are just folders — add one when a new concern emerges (SOC2, pricing, migrations).

deprecate  Retire old knowledge

agent Agent 
> /kluris-acme-sme mark
   infrastructure/auth/old-jwt.md
   deprecated, replaced_by oauth2.md

Flips frontmatter to status: deprecated + replaced_by. Non-blocking, searchable, reversible.

Steering mid-session. Noticed the agent's using an out-of-date fact? Say "that neuron is wrong, update it to say X" and it'll redraft the file for approval — just like remember mode, but against an existing file.

05  ·  MRI — see the whole brain at a glance

One command. Interactive map of everything.

The kluris mri command generates a self-contained HTML file (brain-mri.html) showing every lobe as a coloured cluster and every neuron as a node. Click any neuron to open the inspector panel — frontmatter, excerpt, synapses, and file path, all in one place.

generate the MRI Terminal 
$ kluris mri --brain ngvoicu-sme
✓ scanned 142 neurons across 7 lobes
✓ resolved 318 synapses
✓ wrote brain-mri.html
open the file in any browser · no server required

What's in the MRI

  • clusters  one per lobe, colour-coded — infrastructure, knowledge, projects.
  • nodes  one per neuron; sized by the number of synapses it has.
  • links  synapses drawn as thin lines — you can literally see the knowledge graph.
  • search  fuzzy search in the top bar jumps to any neuron by title or id.
  • inspector  click a node to read frontmatter, excerpt, backlinks, file path.
  • offline  single HTML file · no JS build, no external calls — commit it or email it.
Multi-brain tip: run kluris mri --brain all to regenerate every brain's MRI at once. Great before a team demo.

ngvoicu-sme · real output

Every dot is a neuron · every line is a synapse · every colour is a lobe.

06  ·  Multiple brains, side by side

One kluris. Many brains. Clean slugs.

You'll often have more than one brain on disk — a brain per product, a personal brain, a shared team brain. Kluris keeps them cleanly separated so agents can't mix contexts, and so every command can target exactly the brain you mean.

Listing & switching

kluris list · kluris status Terminal 
$ kluris list
✓  acme-sme       ~/Projects/acme-sme       (project-group)
✓  btb-sme        ~/Projects/btb-sme        (single-project)
✓  ngvoicu-sme    ~/Projects/ngvoicu-sme    (project-group)

$ kluris status --brain all
acme-sme      · clean · origin ahead 0 / behind 0
btb-sme       · 2 uncommitted files · behind 3
ngvoicu-sme   · clean · origin ahead 1 / behind 0
No kluris use. The CLI doesn't hold a stateful "active brain" — every command that touches a brain takes --brain NAME. Zero confusion about which brain you just pushed to.

Agents · one skill per brain

three brains, three skills Inside your AI agent 
> /kluris-acme-sme       learn about billing
> /kluris-btb-sme        learn about the burnout protocol
> /kluris-ngvoicu-sme    learn about specmint

contexts stay separate · no mixing

The naming rule

1 brain  →  skill name is just /kluris.

2+ brains  →  names expand to /kluris-<brain-slug> automatically.

add a new brain  →  kluris doctor renames skills for you in one shot.

Fan-out commands with --brain all

A handful of commands operate on every brain at once — useful for daily housekeeping or before a meeting.

--brain all

dream

maintenance pass on every brain

--brain all

push

push all clean brains to origin

--brain all

pull

pull every brain's latest

--brain all

status

status panel for every brain

--brain all

mri

regenerate every MRI

Non-fan-out commands (create, clone, search, neuron, lobe, branch, wake-up, templates) always target exactly one brain — either the only one, or the one you pass as --brain NAME.
Automation: set KLURIS_NO_PROMPT=1 in CI or scripts. Every interactive prompt becomes non-interactive — safe defaults or a clean error.

Review model · what PRs look like

  • diff Each neuron is a markdown file — PRs show exactly which lines changed.
  • convention Team-lead reviews synapses and status fields like they review code structure.
  • blame Every fact has an author and a commit — disputes become "let's look at the git blame".
  • revert Wrong neuron landed? Revert the commit. Run kluris wake-up. Done.

Host anywhere

GitHub
GitLab
Gitea / self-hosted
Local only · no remote
No vendor lock-in. Kluris never stores your knowledge in our cloud — because there isn't one. It's your git repo, your access rules, your backups. If we vanished tomorrow, your brain keeps working as a folder of markdown files.
Mesh with your codebase? You can even keep a brain as a git submodule inside a monorepo so code + knowledge live together. Or side-by-side. Kluris doesn't care — it just reads the folder.
08  ·  Kluris & specmint · knowledge meets execution

Brain-grounded specs. Real shipped features.

specmint is a sibling plugin for Claude Code / Cursor that turns a feature request into a persistent, resumable spec and then implements it. Wire a kluris brain into the loop and your specs start informed — with real infra, real decisions, real vocabulary.

09  ·  Maintenance & vocabulary

Keep your brain clean and current.

A good brain is a tended brain. Kluris gives you three habits — dream, deprecate, and doctor — that keep the knowledge graph accurate, pruned, and in sync with your agents.

kluris dream

Weekly consolidation

An agent-driven maintenance pass. Suggests merges for duplicates, missing synapses, stale neurons, and weak titles. You approve each change.

terminal Terminal 
$ kluris dream --brain all
agent: 3 duplicates, 2 missing synapses,
       1 neuron untouched since 2025-09
  ? merge a & b into infrastructure/auth? y

deprecate

Retire stale knowledge

Neurons aren't deleted — they're marked status: deprecated with a replaced_by: pointer. Non-blocking, reversible, and agents simply won't cite them in learn mode.

agent Agent 
> /kluris-acme-sme mark
  infrastructure/auth/jwt-v1.md
  deprecated, replaced_by oauth2.md

kluris doctor

Resync after every upgrade

Run it after pipx upgrade kluris to refresh the agent skill files, verify your config, and get a green checklist. Muscle memory worth building.

terminal Terminal 
$ pipx upgrade kluris
$ kluris doctor
✓ skills updated · config ok

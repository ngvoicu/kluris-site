Kluris vs generated graphs

Discovery tools find the map. Kluris keeps the memory.

Graphify and Understand Anything are useful for understanding what exists in a repo or corpus. Kluris is where your team preserves the reviewed decisions, conventions, and cross-project context future agents should trust.

Beat 1 · Set up

Install kluris. Create a brain.

A brain is a git repo of curated markdown that every AI agent on your team can read as a subject matter expert. One command to install. One wizard to create your first one.

macOS · Linux Terminal 
$ curl -fsSL https://kluris.ngvoicu.dev/install.sh | sh
# open a new terminal, then:
$ kluris doctor
Windows · PowerShell Terminal 
> irm https://kluris.ngvoicu.dev/install.ps1 | iex
# from cmd.exe instead:
> powershell -ExecutionPolicy ByPass -c "irm https://kluris.ngvoicu.dev/install.ps1 | iex"
# open a new terminal, then:
> kluris doctor
Update · uninstall Terminal 
$ kluris self-update          # newest release, then kluris doctor
$ kluris self-update --check  # only show the versions
$ kluris self-uninstall       # stops sync services; your brains stay
Install one particular release Terminal 
$ curl -fsSL https://kluris.ngvoicu.dev/install.sh | KLURIS_VERSION=3.0.0 sh
> $env:KLURIS_VERSION = '3.0.0'; irm https://kluris.ngvoicu.dev/install.ps1 | iex

No admin rights. Kluris is one binary in ~/.kluris/bin, and the installer adds that folder to your PATH: open a new terminal so it takes effect. macOS (Apple Silicon and Intel), Linux x86_64 and arm64, Windows x86_64 and arm64. git is the only other tool it uses.

Beat 3 · See

See the whole brain.

One command. A local, interactive map you can share.

$ kluris mri

Open the link in any browser. Commit it, email it, drop it
in Slack — it runs anywhere, with no server.

The MRI is a single self-contained HTML file — no server, no account, no external calls. Run kluris mri, open the link it prints in any browser, and you've got the whole brain to explore. It opens on the brain's lobes as C4-style boxes with the synapse counts between them. Click a folder to drill into its sublobes, click a neuron to read it rendered, and use the breadcrumb or back and forward buttons to walk out again.

It's a tool for three audiences at once: you (spot isolated neurons that should be cross-linked), your team (shared mental model of what we know), and new hires (five-minute onboarding instead of five days of spelunking). Since it's just HTML, you can commit it, email it, or drop it in Slack.

Lines between neurons are synapses — cross-links agents follow to load related context. Because the brain is a pre-digested snapshot, agents spend far fewer tokens orienting to a codebase than without one.

Results are ranked, not filtered: a match in a title or heading weighs more than one in the body, and each ## section is scored on its own, so a hit points at the heading and line where the answer is. Together · One brain, many people

Edit one brain as a team.

The whole team writes to the same brain, and nobody has to pull, push or untangle a merge by hand. Before the agent writes, it syncs with your teammates. After you approve, it commits exactly the files it wrote and shares them. When two people changed the same line, it shows you both versions and asks which to keep. The brain never gets conflict markers, and nothing in your folder changes until you choose.

In your agent you never type these: it shows you what each side changed, asks which to keep (or proposes a merged text for you to approve), then settles it. --ours keeps your version, --theirs the teammate’s, --file a text you merged, and --abort drops the open conflict.

Merged on their own

  • →Changes to different files
  • →The generated map.md and brain.md, rebuilt from the merged brain
  • →created and updated dates: the earlier and the later one
  • →related and tags: both lists joined
  • →Edits to different parts of the same neuron

Left for a person

  • →Overlapping edits to the same lines
  • →A file deleted on one side and edited on the other
  • →Different parent values, or another frontmatter field changed differently on both sides
  • →Until it is settled: no file changes, no commit, no push

Reads

Before they read, kluris wake-up and kluris search fetch your teammates’ changes quietly, at most once a minute, and never touch your files. The changes come into your brain with kluris sync, which the agent runs before every write and whenever you ask for the team’s latest. KLURIS_NO_AUTO_SYNC=1 turns the fetch off.

Always in sync

kluris sync --watch syncs whenever you commit or a teammate pushes. --install-service runs it in the background from login on, as you, with no admin rights: a launchd agent on macOS, a systemd user unit on Linux, a Task Scheduler task on Windows.

$ kluris sync --watch --brain acme
2026-10-27 13:36:28 acme: up to date
2026-10-27 13:36:34 acme: pulled

A file with uncommitted changes is never overwritten. Sync never asks for credentials, runs your repository’s git hooks, and needs git 2.38 or newer. kluris sync --brain all syncs every brain.

What the agent does first

Agent

On the first /kluris-acme of a session, the agent runs kluris wake-up --brain acme --json once, through its shell. It keeps that snapshot — the brain.md body, every lobe with its neuron count, the 5 most recently updated neurons, the glossary, and any deprecation warnings — so it can decode your jargon and avoid citing superseded neurons. It refreshes the snapshot only after the brain changes: a remember or learn, a kluris dream, a kluris sync that merged teammates’ changes, or a file edit you tell it about. Teammates’ changes arrive through the kluris sync it runs before every write, or whenever you ask for the latest.

--brain NAME

Names the brain and skips the picker. Every command that acts on a brain takes it: search, wake-up, status, dream, mri, commit, sync, resolve and companion list / add / remove. Each installed kluris-<name> skill passes it for you, so an agent never meets the picker.

The picker

With two or more brains registered and no --brain, in a terminal, kluris asks which one you mean. The fan-out commands offer all as the last choice; wake-up, search, commit and resolve work on one brain, so they don’t. A brain whose folder has gone missing is marked (missing).

--brain all

Runs the command on every registered brain. Accepted only on the fan-out commands — dream, status, mri, sync and companion list / add / remove. Any other command rejects it with an error.

Scripts and CI

With --json, with no TTY, or with KLURIS_NO_PROMPT=1 there is no picker: kluris exits with an error that lists the registered brains (a JSON object under --json). Always pass --brain in scripts; set KLURIS_NO_PROMPT=1 for wrappers that inherit a terminal but can’t answer a prompt.
